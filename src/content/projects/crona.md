A small tracker designed to stay close to the work instead of becoming another dashboard.

CRONA grew out of the same thinking described in [Why local-first matters](/writing/blogs/why-local-first-matters) and [Designing Crona's architecture](/writing/blogs/designing-cronas-architecture): if the user has to fight the tool to get back to the task, the product is already doing too much.

The project stays intentionally narrow. It tracks what matters now, keeps the shape of the data small, and avoids pretending that every operational detail needs a full analytics surface.

That narrowness is also why the interface can remain calm. The better the structure underneath, the less the UI needs to explain itself.

For more context, the live site is at [crona.work](https://crona.work) and the source is on [GitHub](https://github.com/webxsid/crona). Both are useful references when testing link handling and external resource hints.
